# Auth Storage Lifecycle

## Problem

Нужно проверить, что происходит с авторизацией после переустановки Google Chat бота. Неясно, будут ли OAuth tokens копиться в базе, удаляются ли они автоматически и какие проблемы это может создать.

## Desired Behavior

Поведение авторизации после переустановки бота должно быть понятным и безопасным. Если старые tokens остаются в базе, должна быть описана политика очистки или переиспользования.

## Current Context

Проект хранит refresh tokens через `TokenStorage`. Перед изменением auth flow нужно inspect `src/oauth.ts`, `src/google-chat.ts`, `src/chat.ts`. Контракт `TokenStorage` должен остаться стабильным.

## Plan

- Проверить текущую модель хранения OAuth tokens.
- Разобрать сценарии: переустановка бота, повторная авторизация, отзыв доступа пользователем.
- Описать, когда token должен обновляться, удаляться или считаться устаревшим.
- При необходимости добавить явную очистку старых auth-записей.
- Обновить документацию по auth lifecycle.

## Tests

- Повторная авторизация того же пользователя не ломает `/review`.
- Удаленный или невалидный token приводит к понятному запросу повторной авторизации.
- Local JSON mode продолжает работать.

## Risks

- Можно сломать существующие refresh tokens.
- Можно нарушить совместимость Prisma/PostgreSQL и local JSON mode.
