# Development Workflow Document

Completed: 2026-06-11

## Problem

В проекте есть правила для task-файлов и локального запуска, но нет отдельной
инструкции, как вести задачу от создания до plan mode, реализации, ревью,
архивирования, commit и deploy.

## Desired Behavior

- Добавить документ `docs/workflow.md` с процессом разработки задачи.
- Документ должен описывать:
  - создание task-файла;
  - переход в новый чат и plan mode;
  - согласование итогового плана;
  - реализацию плана;
  - быстрый review через `git diff`;
  - приемку задачи и архивирование;
  - ручной commit с названием архивированной задачи;
  - автоматический deploy при push в `main`.
- Добавить ссылку на документ в `docs/README.md`.

## Current Context

- `docs/development.md` описывает локальный запуск проекта.
- `docs/tasks/README.md` описывает структуру task-файла.
- `docs/README.md` является входной точкой документации.

## Plan

- Создать `docs/workflow.md`.
- Добавить ссылку на `workflow.md` в `docs/README.md`.
- Оставить `docs/development.md` про локальное окружение.

## Tests

- Проверить, что документ создан и ссылка из `docs/README.md` ведет на него.
- Кодовые тесты не требуются, изменение только документационное.

## Risks

- Можно смешать локальную разработку и процесс ведения задач, если положить
  инструкцию в `development.md`.

## Result

Готово:

- Добавлен `docs/workflow.md` с human-facing процессом ведения задачи.
- В `docs/README.md` добавлена ссылка на workflow-документ.
- Правила для агента вынесены в отдельный раздел `Task workflow` в `AGENTS.md`.
- `docs/decisions.md` переименован в `docs/adr.md`, формат ADR упрощен.
