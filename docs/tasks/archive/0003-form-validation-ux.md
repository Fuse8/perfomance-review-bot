# Form Validation UX

Completed: 2026-06-08

Status: Done

## Problem

Сейчас часть ошибок формы может обнаруживаться только после отправки. Например, пользователь вводит `24:00`, отправляет форму и только потом видит ошибку. Также нужно проверить другие формы, как минимум required есть и это уже хорошо.

## Desired Behavior

Очевидно невалидные значения должны подсвечиваться на этапе заполнения формы, до submit, если Google Chat dialog API позволяет это сделать.

## Current Context

Основной сценарий формы находится в Google Chat workflow. Перед изменениями нужно проверить текущую сборку dialog payload и ограничения Google Chat cards/forms.

## Plan

- Найти поля даты/времени и текущую server-side validation.
- Проверить, поддерживает ли Google Chat inline validation для нужных widgets.
- Если inline validation невозможна, улучшить UX ошибки после submit: показать конкретное поле и допустимый формат.
- Добавить ограничения для времени, включая запрет `24:00`.
- В поле выбора сотрудника показывать в выбранном chip исходное имя из Directory,
  не транслитерированное имя для папки.

## Tests

- `24:00` не проходит валидацию.
- Валидное время проходит без регрессий.
- Ошибка объясняет допустимый формат.
- Выбранный employee chip сохраняет исходное имя из Directory.

## Risks

- Google Chat может не поддерживать полноценную inline validation.
- Слишком строгая валидация может заблокировать существующие рабочие форматы.

## Result

Поле времени осталось текстовым `HH:mm`, чтобы избежать AM/PM UI у Google Chat `TIME_ONLY` picker.
Для `textInput` добавлен доступный client-side лимит длины `5`; полноценный regex/pattern Google Chat cards не поддерживают.
Server-side validation отклоняет невалидный формат и невозможное время вроде `24:00`, не запускает workflow и возвращает понятную ошибку с форматом, диапазоном `00:00-23:59` и примером `14:30`.

Выбранный employee chip показывает исходное имя из Directory, а текстовое поле названия папки продолжает получать транслитерированное имя.
