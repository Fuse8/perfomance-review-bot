# Review Status Command

Completed: 2026-06-11

## Problem

Ревьюерам нужен быстрый способ увидеть, у кого из сотрудников Performance Review
просрочен, скоро нужен или пока актуален. Сейчас `/review` запускает workflow для
одного сотрудника, но нет общей команды статуса по всем сотрудникам из папки.

## Desired Behavior

- Команда `/status` собирает сотрудников из root folder ревьюера.
- Для каждого сотрудника бот ищет последнее ревью и считает дату следующего.
- Повторное ревью по умолчанию требуется каждые 6 месяцев.
- Период ревью переносится в `/settings`, чтобы ревьюер мог поменять его вручную.
- Если последнее ревью не найдено, сотрудники показываются отдельным блоком сверху:

```text
Последнее ревью не найдено:
- Бердников Дмитрий
- Иван Иванов
```

- Вверху результата показывается сводка:

```text
🔥 Просрочено: 4
⚠️ В течение 30 дней: 3
✅ Актуально: 18
```

- Основной список сортируется так, чтобы сверху были самые срочные ревью:
  просроченные, затем ревью в ближайшие 30 дней, затем актуальные.
- Основной список выводится таблично. Колонка `Сотрудник` имеет одинаковую
  ширину во всех строках: ширина равна самому длинному имени в выборке, после
  имени добавляются пробелы до начала даты.
- Формат строк:

```text
🔥 Дмитрий Бердников      26.01.2026 → сейчас
⚠️ Иван Иванов           10.06.2026 → 10.12.2026
✅ Петр Петров           20.08.2026 → 20.02.2027
```

- Если ревью просрочено, вместо даты следующего ревью показывается `сейчас`.
- Список сотрудников не ограничивается по количеству.
- Внизу результата показывается подсказка:

```text
🔥 — ревью просрочено
⚠️ — ревью в ближайшие 30 дней
✅ — ревью не требуется
```

## Current Context

В проекте уже есть `/settings`, reviewer root folder ID, Drive integration и
поиск предыдущего review report для конкретного сотрудника. Нужно переиспользовать
эти механизмы и сохранить текущий storage contract стабильным.

## Plan

- Сначала исследовать текущую Drive-структуру и Google Drive API возможности для
  этой задачи. До реализации дать ответ в задаче/плане реализации: `/status`
  сможет получить данные одним broad query или нужен обход папок сотрудников.
- Если возможен один broad Drive query, получить все review report файлы
  минимальным числом запросов и дальше группировать ревью по сотрудникам в памяти.
- Если Drive API/структура не позволяют надежный broad query, получить список
  employee folders и обходить их с ограниченным параллелизмом, например 3-5
  одновременных запросов, а не запускать 10-30 запросов одновременно.
- Не делать отдельный независимый search “последнее ревью” на каждого сотрудника
  без предварительного исследования и явного обоснования.
- Найти текущие обработчики slash-команд и добавить `/status`.
- Найти способ получить список сотрудников из reviewer root folder.
- Для каждого сотрудника найти последнее ревью и дату последнего review report.
- Добавить настройку `reviewIntervalMonths` в reviewer settings с default `6`.
- Добавить поле периода ревью в `/settings` dialog и валидировать значение.
- Рассчитать next review date как `lastReviewDate + reviewIntervalMonths`.
- Разделить сотрудников на группы: без найденного ревью, просрочено, в течение
  30 дней, актуально.
- Отсортировать основной список по срочности и дате следующего ревью.
- Сформатировать результат `/status` с выровненной колонкой сотрудника.
- Добавить логи: старт `/status`, количество сотрудников, количество найденных
  ревью, количество Drive запросов, время выполнения, ошибки Drive lookup.
- Обновить `/info` и документацию команд, если список команд выводится пользователю.

## Tests

- `/status` просит сначала выполнить `/settings`, если root folder не настроен.
- Сотрудники без найденного ревью выводятся отдельным блоком сверху.
- Просроченное ревью выводится с `🔥` и `→ сейчас`.
- Ревью в ближайшие 30 дней выводится с `⚠️`.
- Актуальное ревью выводится с `✅`.
- Дата следующего ревью считается от периода `6` месяцев по умолчанию.
- Custom `reviewIntervalMonths` из `/settings` меняет расчет следующей даты.
- Колонка сотрудника выравнивает даты по самому длинному имени в выборке.
- Сводка считает просроченные, ближайшие 30 дней и актуальные ревью.
- Список сотрудников не обрезается.
- Для 10-30 сотрудников lookup не делает 10-30 независимых search-запросов без
  ограничения параллелизма или broad query.
- Агрегатор выбирает последнее ревью по сотруднику из общего списка найденных
  review report файлов.

## Risks

- Drive lookup по большому числу сотрудников может быть медленным и упереться в
  лимиты Google API.
- Один broad Drive query может быть невозможен, если Google Drive структура не
  позволяет надежный рекурсивный поиск по root folder.
- Названия папок/отчетов могут не всегда позволять надежно извлечь дату ревью.
- Google Chat может плохо отображать моноширинное выравнивание вне code block;
  нужно проверить реальный rendering.
- Настройка периода ревью должна быть совместима с существующими reviewer settings.

## Result

Готово:

- Добавлена команда `/status` без dialog.
- Статус собирается из root folder ревьюера через Drive lookup с пагинацией и
  ограниченной параллельностью.
- В `/settings` добавлена настройка `reviewIntervalMonths` с default `6`.
- Вывод `/status` показывает сводку, сотрудников без найденного ревью и
  выровненную таблицу статусов в code block.
- Даты в статусе выводятся как `MM.YYYY`, без фиктивного дня месяца.
- Обновлены `/info`, README, Google Chat setup docs, Prisma schema и migration.
- Проверено: `pnpm format`, `pnpm eslint:fix`, `pnpm type-check`,
  `pnpm test:quiet`.
