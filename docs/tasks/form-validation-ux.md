# Form Validation UX

## Problem

Сейчас часть ошибок формы может обнаруживаться только после отправки. Например, пользователь вводит `24:00`, отправляет форму и только потом видит ошибку.

## Desired Behavior

Очевидно невалидные значения должны подсвечиваться на этапе заполнения формы, до submit, если Google Chat dialog API позволяет это сделать.

## Current Context

Основной сценарий формы находится в Google Chat workflow. Перед изменениями нужно проверить текущую сборку dialog payload и ограничения Google Chat cards/forms.

## Plan

- Найти поля даты/времени и текущую server-side validation.
- Проверить, поддерживает ли Google Chat inline validation для нужных widgets.
- Если inline validation невозможна, улучшить UX ошибки после submit: показать конкретное поле и допустимый формат.
- Добавить ограничения для времени, включая запрет `24:00`.

## Tests

- `24:00` не проходит валидацию.
- Валидное время проходит без регрессий.
- Ошибка объясняет допустимый формат.

## Risks

- Google Chat может не поддерживать полноценную inline validation.
- Слишком строгая валидация может заблокировать существующие рабочие форматы.
