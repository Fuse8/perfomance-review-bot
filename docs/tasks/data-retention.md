# Data Retention

## Problem

Нужно определить, сколько дней хранить пользовательские данные и как очищать устаревшие записи.

## Desired Behavior

У проекта должна быть понятная политика retention: какие данные хранятся, сколько дней, как удаляются и что остается для аудита.

## Current Context

В проекте есть PostgreSQL/Prisma и local JSON mode. Перед изменением storage нужно сохранить контракт `TokenStorage` и не сломать local JSON mode.

## Plan

- Перечислить типы пользовательских данных, которые реально сохраняются.
- Разделить OAuth tokens и временные workflow/user данные.
- Выбрать retention period для каждого типа данных.
- Добавить cleanup-механику, совместимую с Vercel/Neon.
- Описать retention policy в документации.

## Tests

- Актуальные данные не удаляются.
- Устаревшие данные удаляются по retention rule.
- Local JSON mode продолжает работать.

## Risks

- Нельзя случайно удалить действующие OAuth tokens.
- На Vercel нет постоянного фонового процесса, cleanup нужно проектировать с учетом serverless.
